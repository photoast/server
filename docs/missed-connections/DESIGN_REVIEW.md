# 디자이너 의견 반영 — MISSED / Night Booth

2026-10-30 · 기존 PRD 1.0 이후 제품·프로토타입 변경 결정. 이 문서가 변경된 브랜드/설정 체험의 기준이며, 기존 실제 매칭·동의·보안 원칙은 유지한다. 실제 매칭이나 알림 서비스를 새로 구현했다는 의미가 아니다.

## 1. 핵심 경험

Happy Case: 인스타에서 ‘누가 나올까?’를 보고 유입 → 성인/체험 안내 → 12문항 → 본인 촬영/사진 선택 → 사진 무드·공개 범위·희망 기간·알림 방식 → 봉투를 열어 나의 연결노트 확인 → 네 컷 저장 → 파일럿 지역·가격 체험 티켓.

원하는 감정은 **호기심 → 두근거림 → 내가 편한 연결에 대한 기대**. 첫 문장을 ‘나를 설명하는 검사’에서 ‘내 옆에 어울릴 사람은?’으로 바꾼다. 다만 현재 POC에 실제 상대는 없다. 봉투 앞면·결과·저장 이미지에 DEMO 표시를 유지하고, 봉투에는 본인의 성향과 선택 설정만 담는다. 가짜 상대·외모 등급·임의 일치율로 설렘을 만들지 않는다.

## 2. 의견별 결정

| 의견 | 이번 반영 | 실제 서비스 후속 |
|---|---|---|
| 누가 나올까, 좋은 상대에 대한 기대 | 잠긴 다음 프레임의 `?`, 봉투 열기, ‘내 옆에는 어떤 사람이?’ 카피 | 실제 후보가 있는 경우에만 상대 reveal. 후보 부족 시 대기 |
| 얼굴에 어울리는 사람 | ‘성향과 사진 무드가 어울리는 만남’으로 지향점 표현. 차분한/밝은/자유로운 무드는 **본인이 직접 선택** | 사진 무드를 추천에 사용할지 사용자 연구. 외모 점수/AI 얼굴 평가를 현재 기능으로 주장하지 않음. 자동 분석은 별도 기획·검증·개인정보 검토 이후 |
| 이름만 / 번호도 공개 | 두 가지 radio. 기본 ‘이름만 공개’, 다른 선택은 ‘번호도 공개’ | 이름은 활동명 우선. 번호는 쌍방 호감 + 양측 별도 교환 동의 이후만. 사진 공개 동의도 별개. 현재는 이름/번호 입력·수집 없음 |
| 1주일/한 달/1년 | 세 가지 희망 매칭 기간 선택과 결과/티켓/PNG 요약 | 초기 운영은 1주/1개월 검증 우선. 1년은 장기 컨셉; 무조건 1년 사진 보관이 아님. 갱신·재동의·만료·삭제 자동화 검증 전 출시하지 않음 |
| 매칭 알림톡 | 직접 확인 / 알림톡 희망 선택. 앱 알림은 준비 중으로 비활성 | 발송 공급자/요금·템플릿·수신 근거·전화 소유 확인·해지 경로 검토. 현재 발송/신청 없음 |
| 앱 트래픽 | 웹에서 연결노트 확인이라는 복귀 목적부터 정의 | 실제 재방문/알림 클릭/상호 호감 데이터가 쌓인 뒤 앱/PWA 판단. 앱이 없는데 설치 CTA나 앱 수치를 만들지 않음 |
| 검정 + 팝 컬러 부스 | 차콜 + 라임 한 가지 포인트, 네 컷/봉투/물음표 패턴 | 물리 부스에 같은 워드마크·라임 포털·프레임 라벨 사용 |
| 인스타·인플루언서 | 아래 홍보 가설과 촬영 시나리오 | 실제 광고·DM·섭외·게시 작업은 이번에 하지 않음 |
| 기억나는 고유 네이밍 | 짧은 표기 **MISSED · 미스드**, 풀네임 Missed Connections 유지, 미확인 ® 제거 | 상표·도메인·계정명 가용성 확인 전 확정 상표 주장 금지 |

## 3. 아트디렉션 선택

점수는 시장 반응이 아닌 내부 디자인 판단, 각 5점. 순서: 제품 적합/첫 인지/차별성/실현/접근성/재사용.

| 방향 | 감정·형태 | 서체·색·구성·모션 | 점수 |
|---|---|---|---|
| Night Booth **선택** | 두근거리는 발견, 다음 프레임/봉투 | 큰 sans 영문·핵심 카피 + 한글 명조 연결노트, 차콜/라임, 오브젝트 중심, 직접 눌러 열기 | 5/5/5/5/4/5=29 |
| Signal Red | 강렬한 첫 만남, 신호등 티켓 | 흑백/레드, 촘촘한 안내형, 단일 라이트 전환 | 4/4/4/5/4/4=25 |
| Archive Paper | 조용한 우연, 종이 아카이브 | 기존 명조/크림, 여백 중심, 인쇄 모션 | 3/4/3/5/5/4=24 |

Night Booth는 물리 부스·모바일·저장 프레임에서 동일한 식별 요소를 쓰기 쉽고 디자이너가 원한 팝한 설치물과 맞는다. 별·물음표·네 컷은 code-native 요소, 이미지가 아닌 장식용 생성 사진은 추가하지 않는다. 기존 인물 샘플은 직접 만든 그래픽이라는 표시를 유지한다.

색: 차콜 `#151714`, 라임 `#dcff66`, 종이 잉크 `#f1f3e8`, 보조 `#b7bdac`. 본문 system sans, 연결노트 한글 Nanum Myeongjo(OFL, 자체 subset). 선택지44px 이상·이름/기간 radio·키보드·reduced-motion을 유지한다. 외곽은 검정, 프린트할 스트립은 흰 종이+라임 헤더로 연결한다.

## 4. 데이터 원장과 경계

- 성향: 기존 12문항 정규화, 원문 응답 서버 전송 없음.
- 무드: 사용자 직접 선택, 얼굴에서 추정한 값 아님.
- 공개 범위·기간·알림: 사용자가 선택한 **희망 설정**. 실제 공개/매칭 시작/발송 완료 상태 아님.
- 설정은 답변과 함께 탭 sessionStorage 2시간. 사진은 메모리. 이름·번호는 입력받지 않음.
- 앱은 미출시. 카카오 공급자·템플릿 승인·요금·발송 가능 여부는 미확인. 외부 서비스/API/패키지 추가 없음.
- 1년은 매칭 탐색 희망기간이며 보관 동의와 구분한다. 기존 PRD의 사진 삭제 기간을 자동으로 365일로 늘리지 않는다.
- 성향/프레임/티켓에 같은 설정을 사용하고, 재선택하면 PNG를 무효화해 다시 만든다.

## 5. 후속 모델·이슈 변화 (미구현)

- `MatchingSubscription`: participantId,scope,duration,startAt/endAt,status,renewalDueAt,policyVersion. 초기 기간은 enum, 1년은 feature gate. 예약·과금과 동일 개념으로 취급하지 않음.
- `NotificationPreference`: channel,verifiedDestinationReference,consentVersion,revokedAt. 상대 공개 목적 동의와 수신 목적을 분리한다.
- `NotificationOutbox`: match/version/recipient/channel의 unique key, retry/backoff, provider 상태. 최신 동의/기간/차단·철회 상태를 보내기 직전에 재검사한다. 메시지에는 상대 사진·번호·이름을 넣지 않고 로그인 후 웹에서 확인한다. 예시 카피: ‘새로운 연결이 준비됐어요. 내 연결노트에서 확인해 주세요.’ 실제 알림톡 사용 가능 문구라는 보장은 아님.
- 연락처 공개는 match mutual + 양측 `contact_exchange` allow + 현재 세션 소유 확인을 모두 충족해야 한다. ‘번호도’ 초기 선택만으로 교환 완료 처리 금지.
- 연간 매칭은 30일마다 사진 갱신·목적 재확인하는 방향을 우선 검토한다. 갱신하지 않으면 pause, 사진은 원래 기간대로 삭제. 최종 기간·동의문구는 운영/법무 검토 대상이다.
- 앱은 알림 재방문·결과 확인·상호 선택의 반복 사용을 먼저 검증한다. 설치 수만을 위해 초기 앱을 강제하지 않는다.

후속 이슈: MC-301 실제 구독/만료·갱신, MC-302 검증된 수신 채널/outbox, MC-303 구독과 기존 행사 매칭 연결, MC-304 무드 추천 사용자 연구, MC-305 브랜드 상표·계정·도메인 확인. 이들은 현재 정적 POC에 API가 있다는 뜻이 아니다.

## 6. 인스타·인플루언서 실험안

- 호기심 소재: 검정 부스의 라임 `WHO’S NEXT?` → 내가 찍는 네 컷 → 닫힌 다음 프레임. 카피 ‘내 옆에는 누가 어울릴까?’
- 자기 선택 소재: ‘이름만 / 번호도’, ‘일주일 / 한 달’ 선택 장면 → 봉투 열기. 개인 결정권을 감성의 일부로 보여준다.
- 간직 소재: 흑백 네 컷 + 라임 헤더 + 연결노트 저장. 컷이 예뻐서 저장하고, 경험이 궁금해서 공유하는지 분리 측정한다.
- 인플루언서 참여: 실제 허락받은 촬영·공개·광고 사용 범위를 분리하고 협찬/연출/체험 여부를 명확히 표시한다. 현재 실제 매칭이 된 듯한 반응·성공사례를 연출하지 않는다.
- 기억 장치: 미스드 / 라임 포털 / 다음 프레임 / ‘누가 나올까?’를 반복. 서체·색을 매번 바꾸는 캠페인보다 같은 부스 언어를 유지한다.
- KPI는 다음 실험 가설: 첫 CTA, 설정 완료, 봉투 열기, PNG 저장, 재방문. 실제 데이터나 이미 확보된 참가자로 홍보하지 않는다.

## 7. 수용 기준

1. 390×844 첫 화면에 이름·핵심 질문·CTA·CONCEPT가 보인다. 검정/라임은 설정/결과/PNG까지 일관된다.
2. 촬영 또는 quick sample 모두 설정 화면을 거친다. URL로 reveal을 건너뛰어도 설정 확인 전에는 설정으로 보낸다.
3. 기본 공개는 이름만, 기간1주일, 알림은 직접 확인. 비활성 앱 옵션은 제출할 수 없다.
4. 2개 공개 범위·3개 기간·3개 무드·2개 알림의 유효 enum만 저장. 전화번호 등 추가 입력을 저장하지 않는다.
5. 봉투 버튼은 상대가 아니라 자기 연결노트를 연다. 실제 상대/매력도 점수/가짜 % 없음.
6. 설정을 바꾸면 결과·티켓·새 PNG가 동일한 값으로 갱신된다. 번호는 쌍방 별도 동의 조건을 계속 표시한다.
7. 사진·답변·설정·알림 희망의 서버 전송0건, 메시지 발송0건. 기존 부스/DB/프린터 코드 변경0건.
8. 모바일/desktop happy case·다시 선택·미확인 입력·새로고침·큰 글자·가로 넘침을 확인하고 스크린샷으로 기록한다.

## 8. 렌더 검증·수정 기록

390×844에서 샘플 촬영→설정→봉투→연결노트→PNG→티켓을 실제 클릭으로 확인했다. 번호/1년/차분한/알림톡 선택 및 이름만/한 달로 변경 후 결과·티켓 반영, 새로고침 사진 유실 안내와 설정 복원을 확인했다. 무드 선택 시 본인의 네 컷을 보여준다. 앱은 비활성이며 실제 연락처 입력 필드는 없다.

첫 렌더에서 WHO’S NEXT 스티커가 보조 문구와 겹치고 샘플 표기가 흰 스트립에 묻혔다. 중복 문구를 제거하고 샘플 표기를 오브젝트 아래 독립 줄로 옮긴 후 재촬영했다. 390×844에서 CTA가 화면 안에 노출된다. 320×740에서 document 폭320/scroll 폭320, 1440×900 렌더 확인. 브라우저 console error 없음. 신규 설정36조합·비정상 입력 거부·연락처 추가 키 미보관 테스트 통과. 실제 Safari 실기기 검증과 실제 매칭/알림 서비스는 후속이다.
